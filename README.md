# 幕流 MuFlow

从小说到短剧的智能体制作工作流。用于能读取本地文件、运行Python并调用指定API的智能体环境。

**当前为私有整理版，仓库保持Private。** 工作流基础版本为V2.3.0；本次统一MuFlow名称，不将近期问题讨论冒称已经修复。正式开源许可证和第三方资源再分发范围待确定。

## 工作流程

1. 完整读取小说/剧本和已有身份图，集中确认未明的比例、画风、范围及审核方式。
2. 剧本每批5集，自动接续到全剧完成。
3. 分镜和资产拆解表每批5集，自动接续到全剧完成；正式请求每组30秒，各集长度按剧情计算。
4. 全剧文字、两类提示词和自检交付后，再配置指定API并取得生图许可；资产每批最多20张接续，主图先于派生，派生实际编辑母图。
5. 根据人工、智能体或联合模式验收；联合模式先AI实际审图并汇总，再等人工反馈/采用，修改问题图并复核。
6. 完成全剧跑前预览，等待用户明确启动视频。

项目初始化就建立两个持续更新的本地入口：资产参考图总览、全剧跑前预览。资产拆解表完成后提供实际文件链接。预览分本地审阅与OSS执行核对；能打开页面不等于已具备生成条件。

## 目录

- [muflow/SKILL.md](muflow/SKILL.md)：智能体技能入口。
- [muflow/00_开始测试.md](muflow/00_开始测试.md)：使用和测试说明。
- muflow/scripts：生成请求、批次台账、预览、验收、接口和恢复脚本。
- muflow/references：各阶段操作与边界。
- muflow/assets：空配置模板及内置密封黑袋道具。
- muflow/tests、muflow/validation：合成输入测试与已有验证报告。

## 使用

将muflow目录安装到支持SKILL.md的智能体技能位置，再让智能体完整读取SKILL.md。不同客户端的安装方式可能不同。不要把整个作品项目安装为技能。

示例指令：

> 使用muflow，完整读取我的小说或剧本和人物图，开始任务，做到全剧跑前预览。先确认未明设置，剧本每批5集全部完成，再分镜资产每批5集全部完成；文字完成后再问我API和生图许可。出图后先AI审核汇总，再等我的反馈。不生成视频。

API地址、模型、价格、账号和OSS由使用者在生成配置阶段另配；本仓库不含可用凭据、真实作品或生产日志。Python依赖见[muflow/requirements.txt](muflow/requirements.txt)。

## 检查与限制

基础V2.3.0曾通过208项离线测试，范围是原创合成数据、本地文件及本地模拟服务。这不能代替真实客户端、真实API/OSS或成片质量验收。本次重命名检查结果另见CHANGELOG。

- 确认话术由实际用户发出，智能体负责登记；配对、图片采用和视频启动分开。
- 技能修改确认用于防止智能体在制作任务中擅改技能，不应由智能体从历史记录自动代填。
- 并发问题已记录待优化：当前图片批量执行参数可能与外置配置不统一。运行并发、用户目标、服务商实际额度应分别核对，不能把6或10固定推广为所有用户上限。
- 提示词修改后文字摘要与局部确认的衔接仍需结合真实项目持续测试。
- 未经授权不自动评审视频内容、不做整集自动拼接。精细表演、复杂空间调度和最终成片需要人工把关。
