# 幕流 MuFlow V2.3.0 · 开始测试

先完整读取输入和已有身份图，确认未明的比例、画风、范围及资产验收模式。按全剧分阶段完成；每组真实视频请求固定30秒，各集按剧情计算组数和时长。升级只改本包，不自动安装、不改旧生产项目、不调用真实媒体接口。

输入盘点后用init_project.py创建项目并立即建立两个真实HTML；续接用refresh_progress.py，每批和每次图片事件后同路径刷新，准备不足时也能打开：

- 资产参考图总览：03_资产图/00_资产参考图总览.html：项目运行后在该相对位置生成。
- 全剧跑前预览：07_跑前预览/全剧跑前预览.html：项目运行后在该相对位置生成。

上面是项目输出位置，本技能包不预装作品页面。初次运行实际生成后再给用户可点击的真实文件链接；资产表完成后同时交付它的实际文件入口，不能给不存在的占位文件。资产表、图册与跑前预览持续更新同一入口；后台保存交付版本，显示实际计数、阶段与更新时间。未知总量先写待解析，不编造完成度。

执行顺序：剧本每批5集接续到全剧完成 → 分镜与资产每批5集接续到全剧完成 → 全剧文字及两类提示词交付确认 → 已获生图许可后每批20张接续到本次全量资产完成 → 按选定模式验收图片 → 完整本地／执行核对预览 → 等用户明确启动视频。批次是阶段内部工作量，前5集或20张完成不能标全阶段完成。上下文续接先读台账并继续当前阶段，不擅自缩范围。

新项目须选settings.asset_review_mode：manual人工、agent智能体、joint联合。人工模式不强迫未选的AI视觉审核；智能体模式须真实逐图审查，不伪造用户采用；联合模式分列两方结论。所有模式都核对文件、尺寸、哈希、母图与绑定，最终视频仍须完整当前预览之后的人工明确启动。

joint已确定就先AI实际审核并汇总问题，再等待用户给问题/采用，按授权修图后由AI和人工复核；未回复不能标完成。残血/半血/满血只是通俗状态，技术或所需人工审核未齐不能满血；满血预览也不允许自动视频。

两个视频预览视图读取同一内容：本地审阅可先看真实图片、分镜和缺项，无OSS也能交付；OSS执行核对再查远端对象、同版哈希、有效引用与实际数组。页面可看不代表可以提交视频。真正的请求TXT逐镜写实名、图号、时段、机位动作、逐字台词与必要连续性，不把内部状态JSON直接dump进去。

可直接对制作智能体说：

“使用这套技能，完整读我的小说／剧本和人物图，已有身份固定。按全剧分阶段循环：剧本每批5集全部完成后，再分镜资产每批5集全部完成；先交资产表、正式分镜、两类提示词和自检给我审阅。选定图片验收模式后，按允许的生图阶段每批20张继续。持续给我资产表、图册和跑前预览入口，做到完整预览后等我明确启动视频。”

默认纯发声4.5字/秒、每动作拍2.2秒仅是估算；逐镜对白、动作、停顿、转场与有依据重叠分别核算。放不下自动调整完整单元切点或增组，不删词、异常加速或空镜补秒。资产新图默认16:9，视频比例单独确认，导入原图保留原样并锁身份。

先做完全剧小说转剧本、资产表和分镜等无API文字；启动不追问API/OSS。文字全部完成后，再集中交代“提供／完成API配置并允许开始本批资产生图”，实际许可不可缺。首次生图阶段由使用者配对真实API、图片编辑、模型、费用与传图方式；配置在技能之外，凭证仅用本机引用。配对只读、零生成；缺API继续文字和本地面板，不切换原生或其他通道。现金始终密封不透明，不露钱不撒钱；画面无文字字幕，声音仅对白与必要物理音效，无背景音乐或环境声床。

完整命令见[分阶段执行](references/staged-review.md)，验收方式见[资产交付](references/asset-delivery.md)，内容级批准复用见[审批来源](references/review-controls.md)，实际运行证据见validation目录。本包不宣称离线测试已证明真实客户端不会绕路，也不新增自动视频内容审查或自动拼接。
