# 每组30秒，单集按剧情自动计算

## 固定口径

每个生成组是一条真实逻辑视频请求，固定30秒，组内可以包含多个镜头。失败重试另记attempt及费用，不增加剧情组数。每集没有统一目标时长；不再询问“单条选多少秒”“是否统一150秒/集”。已知设置直接列来源，视频比例、画风、范围等未知创作选择仍按阶段流程确认。

默认纯发声4.5字/秒、每动作拍2.2秒含该动作的视线与停顿，这是可复核的初估，不是实测。用户已有明确读速/动作估算口径就记录复用，不重复问；有特定动作依据可改用action_seconds。已含在动作拍中的视线/停顿不重复加；另有独立停顿或转场才计额外秒数。对白数字/单位/外语按已核对spoken_text统计。无依据不要把所有动作都假定与对白同时发生。

估算 = 纯发声秒 + 动作秒 + 额外停顿秒 + 转场秒 − 有具体证据的对白动作重叠秒。

单集初步组数下限 = 向上取整(剧情估算秒 / 30)。随后按完整台词、动作、转场和承接细排；每镜可容纳、每组精确30秒才通过。语义边界导致组数多于算术下限时自动增加并说明，不把技术组数再交用户选择。不能为了省一组截半句话、删内容、加速台词或改变已批准集界。

例：126秒的初步下限5组=150秒，280秒下限10组=300秒，302秒下限11组=330秒。它们是不同集的计算结果，不是全剧时长选项。149秒接近150秒只能说明估算接近容量，逐组切点/表演不足仍须增组，不能凭整集总量宣称通过。

## 余量与空镜

生成总长可以多于预计有效剧情，人工剪辑决定最后成片长。预览分别列剧情估计、实际组数/生成总长、余量及使用依据。余量优先用于可演的反应、必要动作完成、衔接与剪辑余地；空镜仅在交代地点、时间或其他明确叙事作用时采用，不按缺几秒就自动铺空景、走路、慢动作或重复发呆。禁止padding_only；填写allocation_basis不代表语义已被程序证明，智能体还需核对具体镜头。

预算按实际30秒请求数量、真实接口计价和所有尝试估算/归集，不按最终剪辑有效秒数折算扣费。接口须已核验支持30秒；能力冲突报告缺项，不擅换模型或时长。

## 逐镜数据

每镜增加timing，例如：

~~~json
{
  "action_beats": 1,
  "action_basis": "对应已批准动作：角色察觉来人，转头并停住",
  "pause_seconds": 0,
  "transition_seconds": 0,
  "overlap_seconds": 0,
  "allocation_basis": "反应到动作收尾及剪辑余量；具体表演见本镜action"
}
~~~

action_beats是非负整数，按2.2秒初估；改用具体action_seconds时必须保留动作依据，二者不重复相加。pause_seconds>0需pause_basis，transition_seconds>0需transition_basis；overlap_seconds>0需overlap_evidence，明确哪句哪段与哪个动作同时发生，不能超过对白和动作两者较短项。对完全无动作的对白镜也显式登记action_beats=0。无对白镜需要有具体动作/叙事空镜的时长依据，不能用零需求占时。

镜头seconds为实际分配时间，组内合计精确30秒。timing是最低剧情估算与依据；超过镜头分配则不通过，余量需allocation_basis。程序只验证数据和容量，实际表演合理性由智能体回源检查并留TIMING-30S记录。

## 本地工具与预览

scripts/timing_plan.py project.json --out timing_plan.json

自动汇总所有集与每组/镜的估算、动作/对白拆项、重叠、组数和余量，不调用媒体/API。--pack-atoms可对当前已完整划分且不超过30秒的剧情单元给出保持顺序的分组建议。若单元本身超30秒，返回拆分需求；智能体先按原标点/完整动作拆分，回拼核对台词，再运行，脚本不擅自断句或修改原文。

build_text_preview.py和build_preview.py都显示逐集估算表及逐镜依据，分别纳入文字与视频版本快照。validate_project和文字批准/实际执行检查时长；duration_exception不能将请求改成其他秒数。

升级旧作品时只在副本移除旧episode_target_seconds、设置story_driven和30秒、补齐真实逐镜依据并交新版审阅。保留旧稿和已有合格图，不自动重排旧作品或改动外置API/OSS配置。
