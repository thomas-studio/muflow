# 分阶段执行：全剧循环、固定入口与阶段确认

## 范围与阶段边界

先完整读输入并看已有图，再确认未明设置。独立原稿集标题或绑定当前原稿哈希的已确认分集基准决定全量范围；小说章节不是集数。默认做全剧，只有用户明确限定才缩小本次范围，并同时展示原稿全量和本次范围。不能用只登记了前几集自证全剧完成。

阶段内持续接续：

1. 剧本每批5集，写完一批立即接下一批，直至全剧剧本完成并完成分集、逐句归属及转场核对。
2. 再做分镜与资产，每批5集接续到全剧完成，正式分镜、资产表与两类提示词互校。不得只做完前5集就转去全剧生图。
3. 全剧文字、资产表、正式分镜及两类提示词完整交付并得到当前文字版本允许生图的确认后，图片每批20张继续到本次全量完成；按母图依赖排队，复用合格已有图。批次结束不等于阶段结束，失败/待核项目如实留账。
4. 图片按所选模式验收，完成同源本地／OSS执行核对的完整跑前预览。最终视频只在实际交付当前完整预览之后，取得用户明确启动指令才执行。

这是项目内台账与执行续接，不是自动创建系统定时任务。长上下文或新会话先读取项目与台账，从实际未完成处续接，不重复产出、不擅改范围。授权仍覆盖对应阶段；“做到预览”不自动取消文字生图关卡，也不允许视频生成。用户后续明确修改授权时记录其来源和范围，不预先推定。

## 固定入口与进度

输入盘点后立即在项目建立03_资产图/00_资产参考图总览.html、07_跑前预览/全剧跑前预览.html、08_视频/已出成片预览.html，不依赖API、远端图或媒体生成。资产表完成后提供其实际交付文件链接。资产表、图册与预览持续刷新同一入口，后台保留各次真实交付快照。

准备中可以交页面，但未解析、未开始、生成中、已返回待登记、待审、失败、待核实必须分清，计数与时间来自真实任务/文件/审查记录。缺记录不能猜成未开始或成功；无来源总量时写待解析。

跑前固定页有本地审阅、OSS执行核对两视图，共用同一内容快照、同一组参考及镜头数据。本地可显示真实本地图和缺项；执行视图另外核对必要远端条件。页面可读、内容通过、传输就绪和视频启动授权分别显示。只有固定页存在或本地检查通过，都不能放行视频。

## 项目确认

- 登记完整原稿范围、集数依据、身份图来源、角色对应、SHA256与identity_locked。原图mode=reuse；派生另立ID并保留真实编辑母图链。
- 新图asset_ratio=16:9、scene_ratio默认16:9；导入图可原样保留。video_ratio单独确认，medium/quality明确；不得从旧作品继承比例或画风。
- group_target_seconds=30，episode_duration_mode=story_driven，不设置统一episode_target_seconds。默认4.5字/秒、每动作拍2.2秒仅估算，各集组数/总长按剧情计算，不询问统一150秒等集长。
- settings.asset_review_mode必须选manual、agent、joint。新模板null需集中确认；已有有效选择不逐图重问。旧数据缺字段暂以joint兼容，迁移时明确登记实际选择。
- 启动不追问API/OSS，不让配置阻塞任何全剧文字工作。全剧剧本、资产表、分镜和两类提示词全部完成并交付后，才集中询问指定API/编辑/模型/费用/预算及传输方式；将“配置完成后允许开始本批资产生图”合并交代，实际用户生图许可仍需留证。任意收到API资料不等于授权试生。

## 命令与实际交付

以下从项目所在目录运行，Python使用当前正确解释器，路径按实际项目填写。

1. 新项目运行python scripts/init_project.py 项目目录 原稿文件 --project-id 项目ID，提取原文与空模板后立即刷新三入口；已有项目运行python scripts/refresh_progress.py 项目/project.json恢复刷新。两者不读取凭证、不上传、不生成，准备不全仍输出可读缺项。也可分别运行asset_gallery.py与build_preview.py；每批、每次图片/审查/请求事件后调用refresh_progress同步，外置--profile等文字完成进入生图配置阶段才提供。
2. 完整阅读并得到设置来源后，填settings、输入图与来源范围：workflow_review.py 项目/project.json confirm-project --evidence “实际用户设置来源”。不能代造确认。
3. 按前述批次顺序完成全剧剧本、分镜资产与两类提示词；export_assets.py 资产源JSON 项目/project.json 项目/资产表 --refresh更新资产表四件套，旧版归档history，登记deliverables六项真实文件。所有阶段先做无依赖工作，文本无需API。
4. build_text_preview.py 项目/project.json 项目/文字审阅_v1生成文字审阅快照并同步固定跑前入口。实际交付完整文字后：workflow_review.py 项目/project.json deliver-text --preview 项目/文字审阅_v1 --evidence “真实交付依据”。
5. 用户看过本版本两类提示词并允许生图后：workflow_review.py 项目/project.json approve-text --user-log 真实对话.jsonl --user-line 实际用户行号。引用交付之后的真实消息，不写代理批准字符串。
6. 全剧文字全部完成并交付后，才集中交代API配置与实际生图阶段许可；明确“提供／完成API配置后开始本批资产生图”的范围与预算，不能把任意收到API当允许试生。指定配对接口、编辑契约、范围预算及本次生图许可就绪后，image_api.py按资产ID执行；每批最多20张接续，依赖母图未通过时不强行派生；reuse不调用API。每次保存/恢复结果登记并刷新。不得用原生或替代通道绕过。
7. manual或joint模式：实际交付固定图册后，workflow_review.py 项目/project.json deliver-images --gallery 项目/03_资产图/00_资产参考图总览.html --evidence “实际交付依据”。用户采用时运行approve-images --gallery 同一HTML --user-log 真实对话.jsonl --user-line 实际用户行号，可加--asset-ids指定已确认的实际资产ID，先采用母图。agent模式由智能体实际看图并填写当前版本审查记录，不伪造人工批准。详见[资产验收](asset-delivery.md)。
8. 图片按选定模式通过后，compose_requests.py 项目/project.json 项目/请求_v1编译真正可读请求；目标目录必须是新版本目录。补全完整范围的实际参考、哈希/图序、语义审查及必要远端准备后，再运行build_preview.py 项目/project.json 项目/07_跑前预览 --profile 实际外置配置。普通刷新归档旧版，不自动产生用户授权。
9. 真实交付完整当前预览并记录execution_gate交付回执后停留。用户看完明确启动视频后：workflow_review.py 项目/project.json approve-video --preview 项目/07_跑前预览 --user-log 真实对话.jsonl --user-line 实际用户行号。execution_gate.prepare与batch_video核对当前范围、内容/资产验收、实际传输、模型费用及启动来源才执行。

确认命令只保存已有依据，不生成同意。单条样片、联调和免费试用也没有视频关卡例外；“做到预览”、API配对、总预算或后台通知均不等于视频启动。

## 内容版本与复用

text_manifest锁定源文、已登记剧本/场景/台词/分镜、两类提示词与真实交付文件；内容确认与生成结果字段分开。人工图片采用按asset_id、sha256、subject_digest绑定实际用户来源，普通HTML刷新、时间戳、搜索折叠、审查登记或同对象上传不使同内容确认失效。

真正更换图片、改提示词/母图身份或改台词/动作时只把受影响内容及依赖标待复核，保留其它仍匹配的采用；不能改一张图就要求全剧重新人工采用。服务明确失败但内容参数未变的重试复用阶段许可，仍受预算约束。更新引用或显示不等于可以复用旧视频启动：最终执行始终核对已交付当前完整跑前快照和之后的明确用户指令。

实际语义与视觉审查记录需要当前内容摘要、实际审查人/时间、逐项预期/观察/证据及具体镜号；未执行留待复核。程序结构通过不能代替内容判断。本机脚本检查不能证明真实客户端绝不会绕用其它工具，在线效果、收费和客户端行为另列未测范围。


## 联合验收反馈顺序与页面通俗状态

joint已经确定时不重复问模式：生图完成后智能体先实际逐图审查，汇总问题、原因确定性与待核风险，交用户看图；等待用户实际反馈/采用，按已授权范围修图并保留旧版，随后智能体与人工分别复核。人工未答复时停留，不能填成通过或满血。manual/agent模式保留各自适用分支，不强加未选的审核。

“残血／半血／满血”只作可读概览，旁边须列真实内容、图片、审核和技术/传输状态。文字准备中可残血，图或所选审核未齐可半血；当前范围全部内容与实际图、技术检查和选定审核都齐备才可满血。人工必需模式未取得结论不得满血；满血预览仍不自动生成视频。

## 阶段台账命令（零API）

python scripts/stage_queue.py 项目/project.json init、next、progress分别初始化、指向下一批和查看进度。start 批次ID登记开始；complete 批次ID --artifacts 证据数组.json --evidence “本批实际核对依据”登记保存的产物；fail/block/retry 批次ID --evidence “实际原因”保留失败、阻塞和恢复。台账不自动创作、联网或创建系统定时任务。

证据数组项含path、sha256、kind、episodes；剧本批每集需screenplay，分镜资产批每集需storyboard和asset_table。图片项含path、sha256、kind=image、asset_id，并与实际登记图一致，派生核对母图审计。next仅选择就绪批并保存cursor；图片批complete只证明真实图片已保存，不等于审核通过。全量图片完成后先处于awaiting_review/asset_review，待统一readiness核对内容、实际审核与全剧结构齐备后，才可ready_preview/prevideo_preview；这只允许准备完整预览，不代表允许视频。generation_authorized/video_authorized不会由台账变成true。全剧循环依据独立完整来源，不能由已登记首批或旧临时范围截断，内容语义仍需真实审查。


## 分批产物与固定总表

剧本与分镜每批保存独立文件（例如SC001、SC002、SA001），登记该批产物的实际哈希；合订总稿另行更新，不将反复追加的总稿作为每个旧批次的唯一不变证据。资产拆解表可以持续使用固定入口；stage_queue在complete时自动把asset_table字节冻结到99_工作区/阶段队列证据/批次ID，后续--refresh更新总表不会推翻旧批次。旧批完成只证明当时版本，真实改动已有剧情或分镜须登记受影响批次与下游重做，不能用冻结副本掩盖变更。

每次complete后立即next，智能体执行返回的就绪工作并再次登记，直到当前全剧阶段全部完成或明确等待用户。图片母图在派生前实际核对身份和可编辑条件，已提供的锁定原图可作为真实母图；被退回或仍有未解决反馈的母图不能继续派生。全部图生成后仍要完成AI问题汇总、人工意见与修图复核，不把生产完成当验收完成。
