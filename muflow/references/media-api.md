# 媒体契约、并发与可恢复执行

## 首次配对

本套每次视频请求固定30秒。核验指定接口真实支持30秒；不支持时报告能力冲突，不能让用户重选单条时长或静默改成10/15秒。请求费用按各集实际组数及尝试记录，不把剪辑后的有效秒数当作实际生成费用。

由使用者提供当前服务文档，分别核验image_generate、image_edit、video操作，端点、method/encoding/body、异步查询、响应路径、失败定义、价格上限、模型/尺寸/时长/图数/并发能力。包内只给未配对模板，不预置上游或OSS账号。配置放技能之外，凭证用环境引用。setup_profile.py只做本机校验，verification_evidence填写真实文档或已有获准请求证据，不能把字段齐全当外网联调已通过。禁止为了补“实测”而自动发真实视频；任何协议测试也必须先面板后用户启动，细节见[提交边界](review-controls.md)。

当前标准适配器使用Bearer和JSON或图片multipart；其他鉴权/协议按经核验的项目接入适配，保持相同门槛，不能猜接口兼容。视频body变量model/prompt/images（有序URL数组）/first_image/duration/ratio/resolution/client_key；图片model/prompt/ratio/size，编辑另有input_file（仅multipart）/input_url/input_b64。值恰为$变量才替换原始类型；文字里提到变量不算传图。视频需实际传model、prompt、images、duration、ratio、resolution；固定参数例外必须有契约证据且与实际值一致，单图接口不能偷取多参考中的第一张。响应点路径支持数字下标。文档写支持参考图不等于已经验证“图片编辑”能力。

## 分阶段门槛与唯一通道

本项目只走用户指定且配对的API，缺配置或额度不退回内置/默认/其他通道，单张同脸测试同样受控。先交完整剧本、资产表、分镜和两类提示词，用户明确通过当前文字版本后才出图；图册按已选manual/agent/joint模式验收后再做全片绑定预览；最终视频仍由用户在完整当前预览实际交付后明确启动。具体见[分阶段确认](staged-review.md)。仅有API/预算或旧自动模式不能代替阶段确认。

## 实际图片编辑

母图必须实际查看、通过并SHA256一致。edit必须在已核验图片编辑操作中传正确原图文件/URL/数据，记录操作端点、母图ID/哈希、输入变量、实际请求与结果。端点可与生图同址，但需协议明确区分操作，不凭参数名猜测。阶段、换装、角度和设定图转单人参考都按此执行。

没有可用编辑能力时不得改为重新文生图后声称身份已继承；先明确阻塞，继续无依赖任务。合格已有主图mode=reuse不调用外部接口。母图须通过实际母图准备核验后才能派生；视频资产按已选验收模式通过，未审结果待复核。退回图保留新版本，不覆盖母图或只交最终一张。所有图/片都进入全尝试索引，采用需要区分智能体判断与用户决定。

## 冻结与并发

production.sqlite为执行状态来源。使用workflow_gate和execution_gate核对项目设置、文字确认、用户审图、视频启动及完整范围，再验证实际请求与已交付预览、模型、价格、接口能力和授权。两种授权见data-and-commands：精确面板批准或明确项目预授权；已预授权的多集范围无需重复逐组确认。

所选范围内全部就绪组进入同一跨集滚动池，按集轮转，释放名额立即补位，先完成先收片。不等待第一个视频结果才发第二个，也不硬编码某一作品的并发数。submission/poll/download分别推进，当前runner总生成任务上限受verified_concurrency_limit约束，收片线程另有余量。实际吞吐与限流原因入账；如另配上传/收片独立池，仍遵守已核验额度，不临时改成全剧串行。

每次收费POST前持久保存稳定client_key、尝试序号、完整参数快照和素材哈希；回执使用独立文件，马上登记再解释状态。新尝试清除旧任务ID/旧结果，保留history。使用项目级进程锁与数据库原子写入，输出目录不同不能绕过同项目锁。本地落盘与远端扣费不存在跨系统单一事务；幂等/按client_key查询能力必须单独验证，不能声称做到绝对一次提交。

## 重试分类

- **明确服务failed**：原定稿、同素材/模型重新发起新尝试，第二次失败后仍可继续；受预算、用户停止、配置和已核验上限约束，不偷偷改词/换模型。
- **提交超时/网络断开/5xx且无可识别回执**：结果不明，保存原意图和client_key，查原任务/平台记录；没有权威证据不盲目重发。当前通用runner保留uncertain等待核对，不假设任何平台存在查询接口。确认任务ID后按原任务恢复；需要定制查询适配时先验证协议。
- **已生成但下载失败/地址过期**：继续查询同一任务刷新地址，续传原文件，不再生成。下载错误不消费新生成次数。
- **内容不满意需要改词换图**：属于content_redo，不是failed。必须有对应预授权或用户批准，展示旧结果与具体改动，不自作主张无限付费试片。参数变化用新逻辑版本ID，更新后续台词映射和预览。

预算为每次尝试保守预留；余额不足保留待办，其他可完成下载/报告继续。已知价格超预留停止新增收费，核对新报价。未知费用不写零，不用“第二次必成功”之类承诺。

## 收片与完整性

原任务返回成功后立即保存结果地址并下载到.part。校验Content-Range起止/总长与Content-Length，存在ETag时核对同一对象；不符保留旧片作证据并重新下载该任务结果。恢复不能从错误偏移拼字节。完成后先验非空、传输长度及MP4顶层块边界，包括mdat声明结束不能超实际文件，再原子改名。moov可在文件头，能读时长不能证明尾部完整。完整性检查不解码内容，也不代表影片表演/台词正确。

独立回执和版本文件保留；已保存文件再次恢复须核验容器，不因文件存在就写成功。可选私有备份使用用户配置和已授权的OSS；不改公共权限。无OSS时按平台核验的文件/链接传输。签名到期刷新同对象并更新预览，不更换素材身份；同内容图片采用可复用，最终执行仍核对当前完整跑前快照与视频启动。

## 统一状态与费用

任务阶段区分ready/submitting/running/retry/uncertain/生成成功待下载/downloaded/blocked；downloaded含路径、字节数和SHA256。统一摘要随数据库更新；不要从旧manifest抄完成数。对外另标“文件完整/待用户审片/用户采用”。

reservation为保守上限。billing分别记录平台报告扣费、报告退款、报告净额及费用未知的尝试；每个金额保留对应回执来源。同一次轮询重复出现费用不能重复累加。退款无回执就未知；部分/累计退款口径按服务文档核对，真实平台对账未做就明确未做，不把离线模拟退款称为平台已退费。

首次实接只在用户指定范围与预算内验证。凭证、带签名URL、真实响应可能是私有工作证据，放项目安全位置，不塞公开技能或开源样例。临时新脚本必须经过同样门槛；不能用“一次性试跑”跳过预览、持久化或完整性校验。


## V2.3 本地审阅与执行传输

固定07_跑前预览/全剧跑前预览.html含本地审阅与OSS执行核对，两视图共用内容摘要、实际镜头/图号与请求。本地创建/刷新不读凭证、不上传、不提交媒体；无远端引用也能展示真实本地图、范围与缺项。执行准备仍检查必要远端对象、同版本哈希、有效引用和实际API数组，缺失时保持未就绪，不把本地可看当已可提交。

init_project.py与refresh_progress.py是本地初始化/刷新入口；stage_queue.py只持久化全剧阶段及下一批，generation_authorized/video_authorized不由台账变为true。剧本5集批和分镜资产5集批分别完成全剧后，获准图片20张批接续，母图先于派生。台账完成记录、图册刷新或图片验收不增加媒体执行权限。

真正视频请求仍可通过JSON协议发送，但prompt本身要是可执行分镜，不倾倒内部状态/事件路径。逐字台词、图序与孩子/车辆/道具/伤衣等约束进入真正请求并冻结核对，不只美化网页显示。冻结请求变化需按现有阶段规则更新受影响内容，服务失败原参重试仍保留既有恢复和费用机制。
